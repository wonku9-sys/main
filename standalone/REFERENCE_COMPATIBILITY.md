# 첨부 프로그램·Excel 형식 분석 및 독립판 적용 범위

## 분석 방법

2026-10-20(KST) 제공된 `iamMgr.exe`를 실행하지 않고 PE 헤더, 메뉴·대화상자·문자열 리소스와 DLL 의존성을 읽었습니다. 파일은 9,204,224바이트의 Windows 32비트 MFC 프로그램이며 SHA256은 `98febb12dc39420bff3df5c7ce219095ad7bb0c15bc229d9438263baef219803`입니다. 메뉴 리소스 12개, 대화상자 정의 280개, 문자열 테이블 51개를 확인했습니다. 이 수치는 실제로 모두 작동함을 검증한 기능 수가 아닙니다.

`SQLOdbc.dll`, `ITCME.dll`, `RealGrid.dll`, `SmartChartEx.dll` 등 별도 모듈 의존성이 있어 EXE 하나로 내부 SQL/회계 계산/실행 화면 전체를 확인할 수 없습니다. 해당 모듈을 서영포스에 복사하거나 원본 코드를 추출해 합치지 않습니다. 확인된 조작 방식은 기존 PySide6/SQLite 코드에 독립 구현합니다. 원본 EXE·아이콘·이미지·거래 Excel은 공개 저장소·배포 ZIP에 포함하지 않습니다.

## 제공 Excel 35개

모두 외부 Excel을 실행하지 않고 CP949 구형 XLS 데이터로 읽었습니다. 원본 헤더·행 수·단위 표현을 확인했으며 사용자 운영 장부에 자동 등록하지 않았습니다.

| 구분 | 파일 수 | 처리 |
| --- | ---: | --- |
| 매입 상품 상세 | 19 | 상품/바코드·수량·단가·빈 제목 단위·금액 검토. 일부 음수 반품/불일치는 차단 |
| 바코드·수량만 있는 목록 | 1 | 현재 등록 단가 사용에 별도 동의한 경우에만 관리 초안 작성 |
| 매입리스트(전표 요약) | 6 | 품목 없는 요약으로 판별, 매입 품목으로 등록하지 않음. 가장 큰 파일은 32,896행 |
| 공급사 거래원장 | 3 | 결제·이월·잔액 집계로 구분. 과거 결제나 시작 잔액을 자동 생성하지 않음 |
| 공급사별 매입 집계 | 2 | 집계로 구분. 품목 재고로 이중 등록하지 않음 |
| 공급사 목록 | 1 | 25개 열의 연락처·사업자·계좌·등록일 구조 확인. 이 메뉴에서 공급사 목록 자동 등록은 하지 않음 |
| 단품 판매 / 달력 / 단말 보류 | 각 1 | 매입 상세와 구분하며 매입으로 등록하지 않음 |

원본 상세의 ‘공급사’ 열은 상품장의 현재 공급사를 나타낼 수 있으므로 이를 전표 공급사로 추정하지 않습니다. 명명 규칙이 맞으면 파일명의 공급사·매입일을 추출하고 미리보기에 출처를 표시합니다. 공급사가 없거나 유일하게 매칭되지 않으면 등록/기본 공급사 선택 후 다시 검토합니다. 날짜가 없으면 사용자가 지정한 기본일자를 사용합니다.

등록된 상품코드/기본·확장 바코드 또는 유일한 상품명으로만 매핑합니다. 없는 상품은 임의 생성하지 않습니다. 기본/확장 단위·g/100g 가격·금액·과면세 명시값을 검사하고, 검토 이후 상품/확장단위가 바뀌면 다시 불러오도록 합니다. 같은 바이트의 파일은 중복 제외하지만 다른 형식으로 내보낸 같은 거래는 사용자가 확인해야 합니다.

모든 매입 불러오기는 초안이며 결제·재고·과거 잔액을 만들지 않습니다. 명시하지 않은 과면세는 현재 상품 등록값이고, 단가 없는 파일의 현재 단가 사용은 과거 단가를 복원한 것이 아닙니다. 초안을 실제 확정하면 현재 장부의 등록순 이동평균에 반영되므로 과거 자료 이관 목적이면 운영 장부 대신 별도 시험 장부에서 검토하세요.
