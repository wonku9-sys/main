# v2.4.0rc24 — 매입전표 직접 결제관리 (2026-10-21)

rc24는 미배포 rc23의 Windows 검사 보완을 포함합니다. 실패한 rc23은
사용자용 실행파일로 게시하지 않았습니다.

## 근거와 범위

업로드한 POS투게더 관리자 설명서의 인쇄 쪽수 12~14(매입 작성),
146~151(공급사 결제·현금/카드/계좌이체·당일 수정/취소) 및 사용자의
매입전표 위에 외상매입 결제창이 열린 사진을 참고했습니다.
문서 속 문구는 기능 설명 자료로만 사용했습니다.

사진의 금융 연동·할인(D/C, 쿠폰, 장려금)·어음 자동 처리는 구현 범위가
아닙니다. 기존 대화에서 정한 현금·계좌이체와 카드 수기 기록만 지원합니다.
실제 승인·송금·계좌 조회를 수행하지 않습니다.

## 사용

1. 매입장에서 확정된 매입전표를 선택하고 `결제관리 / 환불`을 누릅니다.
   또는 전표를 열고 하단 `결제 (P)` / Alt+P를 누릅니다.
2. 기존 결제관리와 같은 사용자 재확인을 거칩니다.
3. 거래처·은행·예금주·계좌, 선택 전표 미지급액과 공급사 전체 잔액을 확인합니다.
4. 실제 지급한 현금·계좌이체·카드 수기 금액과 날짜·메모를 입력합니다.
   지급합계와 결제 후 전표 잔액이 자동 계산됩니다.
5. 확인 메시지 후 등록합니다. 매입 품목과 결제 이력은 같은 창의 탭으로 확인합니다.
6. 취소되지 않은 당일 단독 결제를 선택하면 사유를 입력해 수정·취소할 수 있습니다.
   이전 이력은 삭제하지 않습니다. 지난 날짜의 결제는 보존합니다.

초안에서는 기존처럼 결제 입력값만 적용하고, 전표 저장 때 실제 반영합니다.
반품의 기존 환불 절차는 유지합니다. 여러 전표에 배분된 공급사 묶음결제는
잘못된 부분 취소를 막고 기존 결제관리에서 전체 배분을 확인하도록 안내합니다.
저장하지 않은 지급 입력은 재실행 시 자동 복구·재결제하지 않습니다.

## 데이터와 안전성

스키마 214를 변경하지 않고 기존 payments/전표/공급사 원장을 사용합니다.
한 번의 분할 지급은 SQLite 트랜잭션 하나로 처리하며 중간 실패 시 결제·감사기록을
모두 되돌립니다. 선택한 매입전표에만 반영하고 초기 외상·다른 전표에 배분하지
않습니다. 소수점 두 자리까지 보존합니다. 공급사 전체/선택일/전표별 결제 가능액을
함께 검사하며, 조회한 잔액 상태가 달라지면 재조회해야 합니다.
기존 판매 계산원 현금마감은 매출 현금만 집계하는 기존 기준을 유지합니다.
매입 지급 수단별 금액은 공급사 결제 원장에 집계됩니다.

## 검증과 배포

Linux Qt에서 신규 결제·기존 결제관리·스킨·매입 흐름·권한·단축키 관련
81개 검사 통과. 새 창은 850x610, 1000x740, 1250x850에서 주요 입력칸과
저장/닫기 버튼이 창 안에 유지됨을 확인했고 가상 자료로 실제 Qt 미리보기를
생성했습니다. 전체 검사·공유 PC·실행 검사 결과는 VALIDATION.md에 기록합니다.

공개 업로드는 사용자 동의 후 수행합니다. 실행 패키지와 그에 대응하는 소스만
포함하며 실제 업무·개인 DB, 업로드된 DAT/IDX, 암호·인증키는 제외합니다.
Windows 빌드 서버의 네이티브 EXE 검사 성공 여부는 해당 GitHub Actions 실행으로
구분하며, 실제 프린터/DT-970/카드 승인/은행 송금 검증을 뜻하지 않습니다.
