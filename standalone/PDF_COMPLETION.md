# PDF 전체 완성률 · 별도 관리 기준

## 현재 보고

**PDF 전체 기능 완성률: 산정 중 — 검증 가능한 전체 세부 요구 수가 아직 확정되지 않음.**
임의의 75%·90%를 전체 완성률로 표시하지 않는다. 최근의 75%는 특정 개선 묶음의
소스 구현/관련 검사/Linux 전체 회귀/Windows 검증·배포 4단계 중 3단계를 뜻한다.

- 기준 자료: 기존 V0.93B 176쪽 + 새 개별 설명서 45종/108쪽과 사용자 캡처·명시적 변경 요청.
- 새 45종의 수신·본문 추출은 확인했다. 수신 100%를 구현 완성률로 쓰지 않는다.
- 새 개별 자료 중 우선 정밀 대조 기록이 있는 7종은
  `MGR_PURCHASE_REVIEW_20261022.md`에 있다. 이것도 기능 완료 7종을 뜻하지 않는다.
- 두 판의 중복 요구를 합치고, 최신 설명서·사용자의 명시적 변경 사항을 우선한다.
- 명언·한자 풀이·개인 기록처럼 사용자 별도 요청인 기능은 PDF 완성률 분자에 더하지 않는다.

## 앞으로 매번 함께 보고할 항목

1. **이번 작업 진행률:** 어떤 작업 묶음인지, 분자/분모와 남은 단계를 함께 표시.
2. **PDF 전체 완성률:** 전체 세부 요구 집계 전에는 `산정 중`과 근거를 표시.
   집계가 끝나면 `검증 완료 요구 수 / 전체 요구 수 × 100`을 소스 구현률과 구분해 표시.
3. **실행파일 상태:** 소스만 수정 / Windows 시험판 / Windows 실제 검증 완료 / 전달 완료를 분리.
4. 검사 통과 수와 화면 수는 근거로만 쓰며, PDF 기능 완성률로 환산하지 않는다.

## 기능별 완료 판정

PDF 메뉴 → 하위 메뉴 → 입력 항목 → 사용 순서 → 계산/저장 → 재조회/수정/취소 →
권한/마감/동시 변경 → 출력/백업 → 실제 Windows 검증을 요구별로 연결한다.
부분 구현·원본 규칙 미확인·장비 미검증·외부 연동 미지원은 완료로 세지 않는다.
어려운 요구를 임의로 분모에서 제외해 완성률을 올리지 않는다.

특히 현재 남은 기준가/상품 DC/보증금 구성 기록, 전표 분리·합치기·잠금,
공급사 발주→매입 변환, 같은 어음번호 정정, 원본 고급 행사/장비 연동 등을
일반 매입/지급의 구현 완료와 구분한다. 자세한 차이는
`MGR_PURCHASE_PAYMENT_SCOPE.md`, `PURCHASE_FINANCIAL_NEXT.md`, `MANUAL_ANALYSIS.md`를 참조한다.

## 비공개 중간 전달 원칙

사용자는 공개 GitHub 배포를 허용하지 않고 비공개 파일 전달을 선택했다.
중간 작업 완료 시 대응하는 실행 ZIP/소스 ZIP을 같은 빌드 표식·SHA-256으로 묶는다.
실제 Windows 미검증이면 시험판이라고 표시하고 새 `trial-data-v2` 폴더로 시작한다.
고객 DB·개인 기록·원본 첨부·인증정보는 두 ZIP에 넣지 않는다.
링크의 존재/파일 무결성과 사용자 브라우저의 다운로드 성공 여부는 구분한다.
