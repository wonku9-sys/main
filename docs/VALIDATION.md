## Windows 배포물 검증 범위

위 149개 시험과 동결 실행 결과는 Linux 환경의 검증 기록입니다. Windows 실행 검증은 해당 버전 태그의 GitHub Actions 결과를 별도로 확인해야 합니다. 기존 `v1.0.0-windows` 배포물은 새 기능이 없는 이전 버전이며, 1.1.0과 구분해야 합니다.

공개 Release용 포터블 ZIP은 GitHub Actions의 Windows x64 환경에서 PyInstaller로 빌드합니다. Windows에서 전체 테스트와 생성된 EXE의 데모 시작 검증이 성공해야 게시 작업이 실행됩니다. 배포 ZIP과 소스 ZIP의 SHA256도 게시 전에 검사합니다. 원격 작업의 성공 여부는 해당 버전의 GitHub Actions 기록에서 확인할 수 있습니다.

Windows 원격 빌드 검증과 별도로 실제 매장 PC에서의 조작·화면 배율·주변기기 동작 확인은 필요합니다. 개발용 Linux 클라우드에서 Windows PE를 실행하지는 않습니다.

선택 가능한 별도 방식으로 Windows x64용 Python·Qt·SQLite 바이너리를 Linux에서 조합하는 `scripts/windows_portable.py`도 보존합니다. 이 방식은 공식 Python NuGet SHA512, PyPI wheel SHA256, PE x64/DLL 의존성과 ZIP 무결성을 검사하며 `PORTABLE-BUNDLE.json`에 검증 범위를 기록합니다. 이 조립 방식만으로 Windows 실행 검증이 되었다고 주장하지 않습니다.

Windows에서 ZIP 전체를 해제한 뒤 EXE 실행, 최초 관리자 등록, 공급사·상품 등록, 매입·매출, 추가 정산, 종료 후 자료 유지, 엑셀과 백업을 확인할 수 있습니다. 샘플 확인은 `SeoyoungPOS.exe --demo`로 실행합니다. EXE만 따로 옮기면 안 됩니다.

## 구현된 업무 범위

공급사/판매처, 상품, 매입/매출 전표, 추가 지급/수금, 미결제 잔액, 기간별 거래처 원장, 재고 입출고·조정·일괄 실사, 일·월·상품·분류·공급사별 집계, 회원·수동 포인트·기간 특매, 엑셀, 사용자/권한/비밀번호, 감사 기록과 백업을 제공합니다. 실제 업무 DB에는 공용 계정이나 샘플 거래를 만들지 않습니다. 세부 차이는 [설명서 대응 범위](MANUAL_SCOPE.md)를 참고하세요.

지급/수금된 전표의 취소와 이후 재고가 출고된 매입 취소는 제한됩니다. 원가는 거래일의 과거 전체를 재계산하지 않고 실제 등록 순서의 이동평균을 적용합니다. 전용 반품 전표, 기존 자료 자동 이관, 저울·카드 단말기·프린터 연동과 세무 신고는 포함하지 않습니다.

클라우드 설치·시작 지침 저장은 환경 게시와 별개입니다. 새 작업에 게시된 환경의 복원은 아직 검증하지 않았습니다.
