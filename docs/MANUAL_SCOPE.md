# 설명서 참고 범위와 오프라인 업무 기능

참고 자료는 사용자가 첨부한 `POS투게더 관리자프로그램(MGR) 사용설명서 V0.93B`입니다. 아래 쪽수는 PDF 뷰어의 파일 번호가 아니라 설명서 본문에 인쇄된 쪽수입니다. 목차 전체와 주요 업무 설명을 확인해 업무 흐름을 독립적으로 설계했습니다. 기존 제품의 코드·거래자료·계정·전용 하드웨어 프로토콜을 가져오지 않습니다.

이 문서는 설명서의 모든 기능을 완성했다는 뜻이 아닙니다. 화면에 있는 이름만으로 기능을 제공한다고 보지 않으며, 이번 구현의 범위와 차이를 아래에 구별합니다. 테스트 및 Windows 배포 검증 결과는 [검증 결과](VALIDATION.md), 실행·백업 방법은 [README](../README.md)를 함께 확인하세요.

## 단독 실행 원칙

- 한 대의 Windows 10/11 64비트 PC에서 프로그램과 SQLite 파일만으로 업무를 처리합니다. 별도 DB 서버, 웹 서버, 로그인 서버, 인터넷 연결은 필요하지 않습니다.
- 포터블 배포물은 Python·Qt 런타임을 포함하며, 전체 폴더를 압축 해제해 EXE를 실행합니다. 소스에서 최초로 의존성을 설치하거나 개발 PC에서 새 배포물을 만드는 과정은 인터넷이 필요할 수 있습니다.
- 업무 DB와 데모 DB를 분리합니다. 실제 업무용 최초 계정은 사용자가 직접 만들고, 종료 후에도 자료가 보존됩니다.
- 데이터베이스는 로컬 디스크에 둡니다. 네트워크 공유·여러 PC 동시 접속·클라우드 동기화 DB·매장 간 동기화는 지원하지 않습니다.
- 사용자의 요청에 따라 **카드 단말기 연동은 제외**합니다. 영수증·라벨·보고서 프린터 출력도 기존 요청대로 제외하며, 조회 자료는 엑셀 파일로 내보냅니다.

## 계산과 데이터 보존에서 알아둘 점

### 전표 취소는 반품이 아닙니다

취소는 잘못 등록한 원 전표를 안전하게 되돌리는 기능입니다. 이미 지급/수금한 전표, 이후 출고 등으로 재고·원가를 되돌릴 수 없는 매입은 취소할 수 없습니다. 정상 거래 일부를 나중에 반환하거나 환불하는 반품전표는 별도 미지원 기능입니다. 재고 조정만으로 반품대금·미수금·원가까지 처리된 것으로 보면 안 됩니다.

### 실사는 입력한 절대수량으로 현재고를 바꿉니다

여러 상품의 장부수량과 실사수량을 비교하고 확인 후 한 트랜잭션으로 적용합니다. 입력 화면의 장부수량이 그사이 변경되었다면 적용을 거부하여 오래된 수량으로 덮어쓰지 않습니다. 적용 당시 장부·실사·차이 수량과 담당자 이력을 보존합니다. 아직 적용하지 않은 초안은 DB에 저장하지 않으며, 적용된 실사의 취소·초안 재편집·월별 재고 마감은 제공하지 않습니다. 화면을 닫기 전에 적용 여부를 확인하세요.

### 거래처 원장의 결제일과 전표일은 다를 수 있습니다

전표 발생은 전표일, 지급·수금은 각 결제일 기준으로 집계합니다. 전표 최초 등록 시 지급한 금액은 결제 내역에 한 번만 포함합니다. 조회 시작일 이전 거래는 전기이월, 조회 기간 내 발생·정산은 각각 표시하고 기말잔액을 계산합니다. 취소전표는 원장에서 제외합니다. 거래처의 현재 미결제 합계와 과거 기간 말 잔액을 혼동하지 마세요.

### 보고서와 재고평가

단가·금액은 정수 원, 수량은 소수 셋째 자리까지입니다. 서로 다른 단위의 수량을 한 총량으로 더하지 않으며, 그룹 보고서도 단위별로 구분합니다. 매출총이익은 매출액에서 기록된 매출원가를 뺀 값으로 임차료·급여·수수료 등을 뺀 순이익이 아닙니다.

원가는 실제 등록 순서의 이동평균이며 과거 날짜의 전표를 뒤늦게 입력해도 과거 전체 원가를 재계산하지 않습니다. 상품명·분류와 매출의 공급사별 집계는 현재 상품장 기준입니다. 매입의 공급사는 실제 매입전표의 거래처 기준이며 매출 상품의 로트별 공급사를 추적하지 않습니다. 과세 구분은 설명용 상품 속성으로, 부가세 자동 분리나 세무 신고 자료가 아닙니다.

### 업데이트·백업

기존 SQLite에 새 항목과 업무 테이블을 추가하는 방식으로 상품·사용자·전표·결제·재고자료를 보존합니다. 업데이트 전 프로그램의 백업 기능으로 다른 디스크에 복사하고 기존 `data` 폴더를 유지하세요. 로그인은 앱의 업무 권한을 구분하며 DB 파일 자체를 암호화하지 않습니다. PC 계정과 디스크 권한도 함께 관리해야 합니다.

### 포인트와 특매의 적용 시점

포인트 이력의 잔액은 지정일자가 아니라 실제 등록 순서 기준입니다. 과거 날짜를 지정해도 기존 이력의 잔액을 소급 재계산하지 않습니다. 포인트는 매출대금과 별도인 수동 장부이며, 정정은 사유를 기록한 반대 방향 조정으로 처리합니다.

특매는 전표의 상품 선택 시 해당 거래일의 제시 단가로 적용됩니다. 이후 거래일만 바꾸면 직접 입력한 가격을 보존하므로, 필요하면 `기간 단가 적용` 버튼으로 확인 후 다시 적용하세요. 저장된 기존 전표와 상품장 기본가는 소급 변경하지 않습니다.

## 운영 전 먼저 확인할 미지원 업무

실매장에서 전용 반품·환불, 과거 전표 수정, 기존 거래처 외상잔액 이관, 묶음/중량 자동 환산, 계산원 마감, 월재고마감이 필수라면 해당 기능이 추가되기 전 완전 대체 프로그램으로 전환하지 마세요. 실제 자료를 넣기 전 별도의 시험 DB로 공급사·상품 등록 → 매입 → 매출 → 추가 정산 → 실사 → 종료·재실행 → 엑셀·백업까지 확인하는 것이 필요합니다.
